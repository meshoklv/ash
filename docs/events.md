# События локации (EMEVD → `.ashevt` → `src/event`)

**На 14.10.2026.** Скрипт событий Северного прибежища (m18_01) берётся из данных копии DSR, а не пишется руками на C (это меняет план §3.2 «Скрипты зоны на C» — запись в `decisions notes`). Кукер `tools/cook_events.py` превращает EMEVD в компактный байткод, `src/event/event.c` исполняет его с семантикой DS1. Игра видит только интерфейс `EvHost` (запросы + одна «раковина» команд), поэтому тот же код гоняется нативно и на PSP.

Пометки: **[проверено]** — прогоном/чтением данных, **[версия]** — наша реконструкция поведения движка DS1, **[оценка]**, **[придумал]**.

## 2. Конвейер

```bash
tools/.venv/bin/python tools/cook_events.py --out ~/ash-assets/cooked/m18_01.ashevt   # ~4 с, 28 КБ, + .json
tools/.venv/bin/python tools/cook_events.py --list     # экземпляры событий и решения
tools/.venv/bin/python tools/cook_events.py --doc      # таблица §6
tools/.venv/bin/python tools/cook_events.py --gen-header src/event/evops.h   # опкоды для C (коммитится)
```

1. **Расплющивание.** Каждый `RunEvent(slot, event, args)` из конструктора (0) и преконструктора (50) становится экземпляром с уже подставленными аргументами (байт-в-байт, упаковка `struct_args_fmt` с натуральным выравниванием, как в EMEVD) **[проверено: 11810400 читает байты 16–19 аргументов]**. Рантайму не нужна подстановка.
2. **1:1 по строкам.** Каждая инструкция EMEVD → ровно одна наша (иначе собьются `SkipLines`). Константы среза сворачиваются при куке: одиночная игра/хост, NG (цикл 0), мы в m18_01, класс Воин (0), игрок полый, тенденция мира 0, ковенанта нет, предметы Снаглу не бросаем. Неподдержанное → `NOP` (сетевой синк, предзагрузка, ачивки, мыльные сообщения, баффы мультиплеера, человечность).
3. **Урезание** (функции `p0`, `p11810000`, `p11810211` в кукере) и **свои события** 9181xxxx (§6).
4. **Таблицы:** сущности MSB в пространстве PSP (x зеркален, yaw с обратным знаком, как `tools/cook_scene.py`): регионы с формами, объекты, персонажи, коллизии (с именами частей для «стоит на коллизии»), точки возрождения, VFX; сокровища (MSB Treasure), лоты (ItemLotParam), двери-активации (MSB ObjAct + ObjActParam: ключ/эффект, тексты), дропы боссов, русские строки из FMG (подсказки, диалоги, имена предметов и босса; `<?gdsparam@N?>` подставляется при куке).

Файл `.ashevt` — данные FromSoftware (id, позиции, тексты): **только в `~/ash-assets/cooked`, в git никогда**.

## 3. Формат `.ashevt` v1

Точная раскладка — docstring `tools/cook_events.py` и `src/event/evfile.h`. Заголовок `"AEVT"`, версия, 11 пар (число, смещение): экземпляры (16 Б), код (слова), сущности (48 Б, отсортированы по id — бинарный поиск), сокровища (32 Б), лоты (12 Б), предметы лотов (8 Б), строки (8 Б, по ключу), пул UTF-8, корни (какие экземпляры запускать при загрузке: 50, затем 0), активации (32 Б), дропы (8 Б). Инструкция = слово `op | nargs << 16` + `nargs` слов (int или float — по опкоду, таблица `OPS` в кукере = `evops.h`).

## 4. Семантика интерпретатора

Как EMEVD DS1, насколько мы её восстановили:

- **Группы условий** MAIN (0), AND_1..8, OR_1..7. Условие добавляет результат в свою группу; `C_COND` сворачивает группу-источник, запоминает её как «последний результат» (`LastResult`) и очищает. MAIN = ожидание: если ложно, экземпляр откатывается к началу подряд идущего блока условий и ждёт следующего кадра **[версия]**.
- **Skip/Return** по группе, по сравнению, по флагу, по последнему результату; `Return End` ставит флаг события `event_id + slot`, `Return Restart` перезапускает с начала **и тоже ставит флаг [версия: иначе 11815395 гасит полоску босса на балконе — она ждёт `FlagDisabled(11815390)` у события, которое только перезапускается]**. У событий 0 и 50 флаг не ставится.
- **Флаги** — отсортированный массив включённых id (до 1024). «Летучие» флаги `1xxx5xxx` (например 11815393 «бой начат») сбрасываются при перезагрузке и не сохраняются **[версия, конвенция DS1]**.
- **Перезагрузка** (смерть, отдых у костра): летучие флаги сброшены, все объекты/сокровища в исходное, все экземпляры остановлены, заново 50 и 0 — как перезагрузка карты в DS1. Различие Continue/RestartOnRest не нужно: карта перезагружается целиком **[версия]**.
- **Кнопка действия:** каждый кадр все кандидаты (условия `ActionButton` в событиях + «нативные» лут/двери/лестницы/костры) предлагают подсказку, побеждает ближайший; нажатие на следующем кадре срабатывает только у него. Якорь-регион = игрок внутри региона (угол не проверяем); якорь-объект/персонаж = дистанция `max_distance` (или 1,6 м) + угол обзора. `line_intersects` и dummy-смещения не учитываются **[урезание]**.
- **Нативное (в DS1 это движок, не EMEVD):** лут (подсказка «Поднять», выдаёт лоты, флаг лота = «уже взято»), двери (ObjActParam: нужен ключ / эффект 4150 / флаг автоуспеха; успех ставит флаг двери и открывает её, неуспех — «Заперто.»), лестницы (телепорт на верх/низ), костры (разжечь → флаг; отдых → точка возрождения = точка костра + перезагрузка).
- **Объекты:** у дверей и решётки анимация 1 = открыть, 3 = закрыть **[проверено по использованию в m18_01]**; дверь, открытая ключом раньше, остаётся открытой (флаг ObjAct). `ev_push_out` выталкивает игрока из закрытых дверей/решётки, включённых туманов и целой стены шара (OBB по размерам моделей: туман ±2,03 м по dummy 201/202 **[проверено]**, высота 4 м **[оценка]**; двери по FLVER bbox **[проверено]**).
- **Регионы:** коробка = центр нижней грани + ширина/глубина/высота, поворот по Y **[версия: полы m18_01 с этим сходятся — «старт боя» y 197 + 8 над полом 198]**; цилиндр — тоже от низа; сфера — от центра.

## 5. Интерфейс с игрой

Заголовок `src/event/event.h`, библиотека `ash_event` (`add_subdirectory(src/event)`, `target_link_libraries(... ash_event)`).

```c
static Ev g_ev;                               // ~2 КБ + ev_mem_size() (7,7 КБ на m18_01) из арены зоны
u8 *f; int n = world_read_file("m18_01.ashevt", &f);       // любой 4-выровненный буфер, живёт с зоной
ev_load(&g_ev, f, n, zone_alloc(ev_mem_size(f, n)), &(EvHost){ game, ev_query, ev_chr_pos, ev_cmd });
ev_save_read(&g_ev, save_blob, save_len);     // если есть сейв
ev_start(&g_ev);
// каждый кадр (шаг симуляции 1/30):
EvInput in = { {p.x, p.y, p.z}, p.yaw, pad_pressed(TRIANGLE /* «действие», the controls design notes */), pcol_part_name };
ev_tick(&g_ev, dt, &in);
ev_push_out(&g_ev, p.pos, capsule_r, player_anim == 7410 /* проход сквозь туман */);
hud_prompt(ev_prompt(&g_ev));                 // UTF-8, русский
// смерть игрока: после экрана «ВЫ ПОГИБЛИ» -> ev_player_died(); на EV_CMD_RELOAD — ev_respawn(&g_ev, pos, &yaw)
```

`EvHost.query(what, id)`: `EVQ_HP_RATIO` (0..1), `EVQ_DEAD` (1 после анимации смерти), `EVQ_ATTACKED`. `chr_pos(id)` — позиция/yaw персонажа (id из MSB: демон 1810800, полые 18101xx…). `cmd(EvCmd*)` возвращает секунды, на которые событие ждёт (анимация, затемнение). Что игре делать по командам:

| Команда | Игра делает |
|---|---|
| `CHR_SET` (ENABLE/AI/INVINCIBLE/HPBAR/TEAM) | включить/выключить врага, его ИИ, неуязвимость |
| `CHR_ANIM` id, a | проиграть анимацию; **7410** у игрока = проход сквозь туман (~1,5 с, 2 м вперёд, туман не блокирует), **9060** у демона = прыжок с потолка; вернуть длительность |
| `MOVE` / `FACE` / `NEST` / `STANDBY` | телепорт/поворот персонажа; гнездо и стойка ожидания демона (9000 = висит в воздухе) |
| `OBJ_ANIM` / `OBJ_STATE` | двери, решётка (`src/world`: `world_obj_enable`, матрица объекта); `f[0] = -1` — сразу конечная поза |
| `VFX` | туман-стена (VFX 81802/81805/81806) вкл/выкл |
| `MAPCOL` | коллизия 1813121 на время закрытия решётки |
| `BOSS_BAR`, `BOSS_START`, `KILL_BOSS`, `SOUND` | полоска HP «Демон Прибежища», музыка босса, души + «VICTORY ACHIEVED» |
| `ITEM` | «Получено: …» (инвентарь событий в `Ev` — ключи; оружие/эстус игра берёт себе по ключу предмета) |
| `OBJACT` | анимация игрока у двери (7110/7120), при неуспехе — текст «Заперто.» |
| `DIALOG` | окно с текстом («Использовано: …», «Заперто при помощи устройства.») |
| `LADDER` | затемнение + телепорт на `pos/yaw` (урезание: без лазания) |
| `BONFIRE_LIT`, `REST`, `RELOAD`, `SAVE` | костёр, отдых (затемнение), респаун врагов/HP/эстус, запись сейва |
| `CUTSCENE` | затемнение + титр «Северное прибежище нежити» (вместо кат-сцены) |
| `BALL` | шар катится `pos → pos2` со скоростью `f[0]`, урон сферой радиуса `f[1]`; вернуть время |
| `BOMB` | бросить огненную бомбу из `pos` в `pos2` |
| `END_DEMO` | экран «Конец демо», дальше скрипт стоит |

**Сейв / `src/progress`.** Модуля `src/progress` в `main` пока нет. Ожидаем: progress владеет файлом сейва (`sceUtilitySavedata`, план §3.11) и кладёт в него блоб событий: `ev_save_size()` / `ev_save_write()` на `EV_CMD_SAVE` и у костра, `ev_save_read()` при старте до `ev_start()`. В блобе — постоянные флаги (взятый лут, открытые двери, пройденные туманы, флаг 16 «демон убит», зажжённые костры), точка возрождения, предметы-ключи. Души, HP, эстус, пятно душ — в части progress. Проверка «у игрока есть предмет» — `ev_has_item(key)`, `key = cat << 28 | id` (cat 0 оружие/щит, 4 расходник/ключ).
