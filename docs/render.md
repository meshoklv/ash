## 1. Что сделано и как выглядит

Скрины ДО/ПОСЛЕ (одни и те же ракурсы, одна поза, кадр слева — как рисует `src/game` на 14.10, справа — `RF_ALL`), mp4 «до | после» (облёт 4 с + наезд к факелам 2,7 с):
- `~/ash-assets/shots/night/R6-visual/` — `arena_c{0..3}_sbs.png`, `hall_c{0..3}_sbs.png`, `arena_before_after.mp4`, `hall_before_after.mp4` (вне git, контент DS);
- полный прогон с логами, кадрами покрытия и `*_costs.json` — рабочая папка прогона `shots/night-visual/final-{arena,hall}/`.

Ракурсы: c0 «герой» (за рыцарем на демона), c1 «общий» (сверху-сзади), c2 «пол вдаль» (низко, проверка мипмапов/тумана), c3 «факел» (ближайший к рыцарю факел его этажа). Арена = верхний зал c2232, яма = нижний зал c2230. **[проверено: кадры просмотрены]**

## 2. Мипмапы (`RF_MIPS`)

- `tools/texmip.py <scene>.ashm` → `<scene>.ashmip` рядом. Уровень = бокс-фильтр 2×2 в RGBA (альфа по покрытию ≥ 0,5) → обратно в **ту же CLUT** (ближайший непрозрачный цвет, KD-дерево). Одна `sceGuClutLoad` на всю цепочку. Уровни до 16 px шириной (блок свизла 16 Б × 8 строк), максимум 7 доп. уровней.
- Рантайм: `render_tex_bind()` = `sceGuTexMode(psm, n, 0, 1)` + `sceGuTexImage(level…)` + `sceGuTexLevelMode(GU_TEXTURE_AUTO, bias)` + `GU_LINEAR_MIPMAP_LINEAR` (можно `GU_LINEAR_MIPMAP_NEAREST`).
- Память: арена +64 КБ к 196 КБ (+33 %), яма +52 КБ к 160 КБ **[проверено: вывод texmip.py]**.
- Эффект: высокочастотная энергия (дисперсия лапласиана) полосы пола в кадре — **−20…−33 %** на всех 6 ракурсах (напр. арена c0 1317 → 918, яма c1 1110 → 754) **[проверено: post-скрипт по кадрам ДО и «только мипмапы»]**. Это и есть меньше мерцания дальних плит в движении.
- Для `cook_world.py` (`.ashw`, CLUT4/8): `from texmip import mip_levels, swizzle` → уровни на каждую текстуру; формат пака мира — решение его автора (нужны `n_levels` + смещения уровней в `WorldTex` или отдельная запись `"mips"` в `.pak`).

## 3. Свет карты: вершинный свет + второй проход (`RF_VLIT`, `RF_LIGHTPASS`)

**Источники — из данных DS1** **[проверено: MSB m18_01 + a18_DrawParam]**:
- MSB `lights` (32 события: `松明_xx`, `PL 松明_xx`, `gate_light`) → `PointLightBank[point_light_id]`: 15 «B1松明 小» (0,5→3,5 м, 255/150/100, сила 1,8), 16 «B1松明 大» (2→5 м, 235/150/100, 3,0), 18 gate_light; + MSB `vfx` 530 (пламя факела) без события света — как ряд 15 **[версия]**.
- Радиусы ×1,6 — в DS1 эти точечные источники рассчитаны на персонажей, на карте пятна выходят крошечными **[придумал]**.
- Арена: 5 источников (ворота сбоку + 2 на балконе). Яма: 15 (6 на колоннах, 4 у стен, 5 соседних помещений).

**Вершинный свет (`--vertex-out`, главный, 0 мс в рантайме):** свет каждой вершины = Σ источников (smoothstep затухания, N·L, тени лучом по Havok-коллизии `.pcol`) и **прибавляется** к запечённому цвету вершины (`цвет += свет × 255 × 0,4`); GE умножает его на текстуру — получается честное «альбедо × свет». Выход — копия `.ashm` того же размера (`arena_vlit.ashm`), интегратор просто грузит её вместо исходной.

**Второй проход (`RF_LIGHTPASS`, по флагу):**
- Лайтмап сверху (XZ) 128×128 CLUT8 (≤16 КБ + 1 КБ палитра), тени от коллизии, точка приёма — первый пол под тексом ниже факела.
- Рисуется **аддитивно** (`GU_FIX 1 + GU_FIX 1`) через проекцию текстуры от позиции вершины: `sceGuTexMapMode(GU_TEXTURE_MATRIX)` + `sceGuTexProjMapMode(GU_POSITION)`, матрица через `sceGumLoadMatrix` в режиме `GU_TEXTURE` (через `sceGuSetMatrix` нельзя — `sceGumDrawArray` перезаливает единичную матрицу gum) **[проверено: отладочный кадр `RF_DEBUG_LM`]**. Второго набора UV и лишних вершин нет — те же вершины, свой список индексов.
- Почему не умножение «×2»: запечённый пол у факелов почти чёрный (8–16 из 255 в кадре), умножение света не даёт **[проверено: значения пикселей дампа]**.
- Рисуются только **≤2500 самых ярких** треугольников рядом с источниками (горизонтальный радиус + окно по высоте −7…+4 м — свет не протекает на другой этаж). Мерцание — пересчёт палитры 1 КБ на кадр (CPU ~256 операций).
- Ограничение: проекция сверху — вертикальные стены получают свет «пола под ними» (полосы вверх по колоннам у факелов). В яме это заметно, на арене выглядит как отсвет.

## 4. Туман (`RF_FOG`)

- `FogBank[fog_id]` коллизии пола из MSB: арена `h0005B1` → ряд 23 «B1教会»: 10→60 м, белый, alpha 90; яма `h1600B1` → ряд 22 «B1下水»: −20→300 м, (60,90,60), alpha 150 **[проверено: DrawParam]**.
- Перевод в линейный туман GE **[версия]**: near = start, far = start + (end−start)/(alpha/255) (≤160 м), цвет = цвет DS1 × 0,32, фон (clear) = цвет × 0,45 **[придумал, на глаз]**. Арена: 10…152 м, `0x525252`; яма: −20…160 м, `0x131d13`.
- `render_fog_visible(cx,cy,cz,r)` — отсечение батча дальше far (у арены/ямы ничего не отсекает: залы меньше 60 м).
- Для мира: `cook_light.fog_table(map, area)` → `{имя коллизии: туман}` — можно хранить в `ZoneCol` и менять туман при смене ячейки.
- Честно: на кадрах туман почти незаметен — залы маленькие, DS1-туман в них слабый. Сильнее — только «на глаз».

## 5. Свет персонажей и обводка (`RF_CHARLIGHT`, `RF_RIM`)

- `LightBank[ambient_light_id]` коллизии пола: арена ряд 35 «B1キャラ(教会)», яма 36 «B1キャラ(下水)» — три направленных света (RotationX/Y, сила 100/500/200 %) + TopDown/BottomUp **[проверено: DrawParam]**; трактовка RotationX как высоты источника — **[версия]**. Самый сильный → яркость 0,48, свет слабее 30 % от сильнейшего выкидывается (экономия), ambient = (TopDown+BottomUp)/2 × 0,25 + 20 **[придумал]**.
- Свет 3 — ближайший факел как точечный (затухание 1/(0,6 + 2,4·d²/r²), мерцает) **[придумал]**.
- Обводка: второй скиннинговый проход, текстура-кольцо по сферической карте из нормали в пространстве камеры (`GU_ENVIRONMENT_MAP`, источники 2/3 = векторы «вправо»/«вверх» камеры), аддитивно, тёплая ~35 %. У рыцаря 16 из 29 чанков помечены альфой — `render_char_rim(chr, skin, 1)` включает их.
- Результат на кадрах: рыцарь и демон читаются на тёмном фоне, было — силуэты сливались **[проверено: c0/c2 обеих сцен]**.

## 6. Тени-кляксы и эффекты (`RF_SHADOWS`, `RF_FX`)

- Клякса: сетка 3×3 (8 треуг.), высоты из `pcol_floor` по колбэку, подъём 4 см, мягкая текстура 32×32, затемнение 70 %; в воздухе слабее и шире. На тёмном полу арены почти не видна — работает в освещённых местах.
- Частицы (пул 320, `GU_SPRITES` в 3D): огонь факела 22/с (костёр 46/с) + угольки + мерцающий ореол; искры удара 14 (парирование 22, голубоватые) + вспышка; пыль переката 9 спрайтов (альфа). Факелы зоны берутся из `.ashl` автоматически (`fx_zone_fires`).

## 7. Стоимость (модель PSP-est, **без калибровки на железе**)

Тест-EBOOT собирается и в варианте `ash_rtest_est` (обёртки `src/perf`), на каждый кадр — строка `PSPEST`. Кадр «только эффект X» минус кадр «ДО», одна поза и ракурс; 4 ракурса × 2 сцены **[оценка — модель, не железо]**:

| Эффект | +мс GE (мин…макс) | +треуг. | +пикс. (с перерисовкой) | Память | Вывод |
|---|---|---|---|---|---|
| Туман | 0 | 0 | 0 | 0 | бесплатно |
| Мипмапы | 0* | 0 | 0 | +33 % текстур (+64 КБ арена) | *модель мипмапы не учитывает; на железе ожидаю выигрыш (меньше промахов кэша текстур 8 КБ) **[версия]** |
| Вершинный свет (`--vertex-out`) | 0 | 0 | 0 | 0 (замена `.ashm`) | **по умолчанию** |
| Второй проход света | +1,1…+9,8 | +1,4…1,7 тыс. | +2,7…109 тыс. | 32 КБ `.ashl` | дорог вблизи факела (заливка); только «геройские места» |
| Свет персонажей (3–4 источника) | +1,4…1,5 | 0 | 0 | 0 | ок |
| Обводка | +5,2…6,0 | +3,5…3,8 тыс. (скиннинг) | до +34 тыс. | 4 КБ | **дорого**: только игрок или выкл. |
| Тени-кляксы (2 шт.) | 0…+0,5 | 16 | до +6 тыс. | 4 КБ | ок |
| Частицы | +0,02…+2,3 | 64…206 спрайтов | до +15 тыс. | 4 КБ + 13 КБ пул | ок; в яме (15 факелов) до 2,3 мс |

Итог кадра ДО → ПОСЛЕ (`RF_ALL`): арена 25…36 → 38…45 мс GE, яма 39…64 → 52…79 мс. **Важно:** уже кадр «ДО» на арене на грани 33 мс, а в яме за бюджетом — сама сцена (40 тыс. треуг. без упрощения) тяжелее бюджета; эффекты это не меняют, но и не помогают.

Рекомендация: `RF_PSP_DEFAULT = FOG | MIPS | CHARLIGHT | SHADOWS | FX | VLIT` ≈ +1,5…4,3 мс GE по модели; `RF_LIGHTPASS` — только арена босса/костёр и если после дня с PSP останется запас; `RF_RIM` — только на игрока или выкл. Подсчёт пикселей проходов делается кадром `RF_DEBUG_COVER` (логическая операция SET = белый, `post.py` считает).

## 8. Патч для интегратора

**CMake.** В корневой `CMakeLists.txt`: `add_subdirectory(src/render)`; у `ash_game` в `src/game/CMakeLists.txt`: `target_link_libraries(ash_game PRIVATE ash_render ...)`. Отдельно собирается так:
```bash
. scripts/env.sh && psp-cmake -S src/render -B build/render -G Ninja -DCMAKE_BUILD_TYPE=Release && nice -n 19 cmake --build build/render
```

**Кук (раз на сцену/зону):**
```bash
tools/.venv/bin/python tools/texmip.py ~/ash-assets/cooked/arena_nochars.ashm            # -> arena_nochars.ashmip
tools/.venv/bin/python tools/cook_light.py --scene ~/ash-assets/cooked/arena_nochars.ashm \
    --pcol ~/ash-assets/cooked/arena.pcol --floor h0005B1 \
    --out ~/ash-assets/cooked/arena.ashl --vertex-out ~/ash-assets/cooked/arena_vlit.ashm
# яма: hall_nochars.ashm, hall.pcol, --floor h1600B1, hall.ashl, hall_vlit.ashm
```
Стейджинг (`scripts/shoot-game.sh` и т. п.): `arena_vlit.ashm` → `scene.ashm`, `*.ashmip` → `scene.ashmip`, `arena.ashl` → `scene.ashl`.

**`src/game/main.c`** (порядок вызовов — в комментарии `render.h`):
```c
#include "render.h"
#include "render_chr.h"
static RenderZone g_zone; static RenderMips g_mips;
static int floor_cb(void *c, float x, float z, float yt, float yb, float *h)
{ (void)c; return g_has_col && pcol_floor(&g_col, x, z, yt, yb, 0.5f, h) >= 0; }

/* после load_all(): */
render_init();
g_render.flags = RF_PSP_DEFAULT;          /* + RF_LIGHTPASS на арене босса, по настройке */
{ u8 *f; int n;
  if ((n = ash_load_file("scene.ashmip", &f, NULL, 0)) > 0) render_mips_load(&g_mips, f, n);
  if ((n = ash_load_file("scene.ashl", &f, NULL, 0)) > 0 && render_zone_load(&g_zone, f, n) == 0) {
      render_zone_apply(&g_zone); fx_zone_fires(&g_zone); } }

/* кадр: после sceGumStoreMatrix(&view) и ash_mat_mul(&vp, ...), вместо sceGuClearColor/sceGuFog: */
render_begin_frame(&view, &proj, cam.eye, DT);      /* сам ставит clear colour и туман */
sceGuClearDepth(0); sceGuClear(GU_COLOR_BUFFER_BIT | GU_DEPTH_BUFFER_BIT);
int tris = scene_draw(&sc, &vp, &nb);               /* scene.c: см. ниже */
render_light_pass_ashm(sc.vert, sc.batch, sizeof(AshmBatch));
/* персонажи: вместо sceGuEnable(GU_LIGHTING)...sceGuDisable(GU_LIGHTING) */
float chest[3] = {pl.pos[0], pl.pos[1] + 1.2f, pl.pos[2]};
render_char_light_begin(chest); tris += chr_draw(&g_k.chr, g_k.skin); render_char_light_end();
tris += render_char_rim(&g_k.chr, g_k.skin, 1);    /* только игрок; при RF_RIM */
/* ... то же для демона без rim ... */
render_shadow_blob(pl.pos, 0.55f, floor_cb, NULL);
render_shadow_blob(g_d.pos, 2.2f, floor_cb, NULL);
render_fx_draw();
render_end_frame();
/* события: fx_hit_spark(точка, направление, парирование) при попадании/блоке; fx_roll_dust(pl.pos, pl.yaw) в начале переката */
```
**`src/game/scene.c` `scene_draw`:** блок `sceGuClutMode … sceGuTexFlush()` заменить на
`render_tex_bind(GU_PSM_T8, t->w, t->h, s->file + t->off_clut, s->file + t->off_pix, mips, b->tex);` (передать `RenderMips*` параметром или глобалом) и добавить `if (!render_fog_visible(b->cx, b->cy, b->cz, b->radius)) continue;`. В конце — `sceGuTexFilter(GU_LINEAR, GU_LINEAR)`.

**`src/world` (`.ashw`, s16-вершины):** то же `render_tex_bind` (psm T4/T8) в `world_draw`. Второй проход для мира: `render_light_pass_begin(); render_light_pass_draw(sub, GU_TEXTURE_16BIT|GU_COLOR_5650|GU_VERTEX_16BIT, verts, b->pos_off, b->pos_scale); render_light_pass_end();` — **кукер подмножеств для `.ashw` не написан** (`cook_light.py` сейчас читает `.ashm`); вершинный свет для `cook_world.py` — функциями `msb_lights()` + `light_at(points, normals, lights, col_tris)` + прибавить к RGB565-цвету.
