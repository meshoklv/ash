# Коллизия карты `.pcol` — формат и API (M4a)

_14.10.2026. Переиспользуйте этот модуль (src/game/pcol.c), не дублируйте. Расширение на всю карту — это `SCENES` в кукере + при необходимости сетка/индексы шире (см. «Пределы»)._

## Откуда данные **[проверено]**

- Источник — **Havok-коллизия карты**, не визуальный меш: `map/m18_01_00_00/h18_01_00_00.hkxbhd/.hkxbdt` (hi-res, по ней ходит игрок; `l*` — low-res, не используем).
- Читается чистым Python: `soulstruct.havok.fromsoft.darksouls1r.MapCollisionModel.from_bytes(entry.data)` → `meshes[]` с `vertices3D`, `face_vertex_indices`, `material_index`. 47 моделей m18_01 читаются за ~0,1 с.
- Расстановка — MSB `collisions` (translate/rotate, `camera_1_id`). В m18_01 все коллизии стоят в (0, 200, 0) без поворота.
- Объекты с коллизией (o8510 — центр пола арены) — `obj/<model>.objbnd` → `<model>.hkx` тем же `MapCollisionModel`, расстановка по MSB `objects`.
- Кукер: `tools/cook_collision.py --scene arena --out ~/ash-assets/cooked/arena.pcol` (или `--scene hall` — яма Демона-отступника под ареной) — берёт треугольники всех частей, чьи AABB задевают бокс сцены, сваривает вершины (1 мм), выкидывает вырожденные, зеркалит x → −x (PSP-пространство, как `cook_scene.py`; после зеркала `cross(b−a, c−a)` — внешняя нормаль).

- **arena** (верхний зал, бокс FS x −9,5…16,5, y 196…226, z −44…−0,5): **17 066 треугольников** (20 частей + объект o8510), 13 369 вершин, **404 КБ**, сетка 13×22; пол y 197,6–198,2, строка LockCamParam 103.
- **hall** (яма c2230, бокс x −13,5…19,5, y 180…199, z −41…4,5): 16 537 треугольников из 23 частей (пол h0016B1 y 182,25, в центре курган до +1,2 м), 387 КБ, сетка 17×23 по 2 м, в среднем 84 треугольника на ячейку, максимум 272.
- Рядом `<out>.spawn` (текст, PSP-пространство, yaw в радианах): `player x y z yaw` (точка из конфига сцены) и `target <модель> x y z yaw` (запись MSB). Игра читает их как `scene.pcol` / `scene.spawn`.

## Формат `.pcol` v1 (little-endian, секции выровнены на 16, смещения от начала файла)

| Секция | Размер | Поля |
|---|---|---|
| Header | 80 Б | `"PCOL"`, u32 version=1, n_vert, n_tri, n_part, nx, nz, n_list; f32 x0, z0, cell, pad; u32 off_vert, off_tri, off_part, off_cell, off_list, pad[3] |
| Vertex | 12 Б | f32 x, y, z (PSP-пространство) |
| Tri | 10 Б | u16 v[3], u16 material (`MapCollisionMaterial`, +100/+200/+300 — варианты для лестниц), u8 part, u8 flags (0) |
| Part | 24 Б | char name[16] (имя MSB, напр. `h0016B1`), s32 cam_row (`camera_1_id`, −1 = строка 0 LockCamParam), u32 pad |
| Cell | 8 Б | u32 start, u32 count → в список; nx·nz ячеек по `cell` м на плоскости XZ, порядок `[z][x]`, начало (x0, z0) |
| List | 2 Б | u16 индексы треугольников |

Пределы v1: вершин и треугольников < 65 536, частей < 256 (u16/u8). Для всей карты — либо несколько `.pcol` по зонам, либо v2 с u32-индексами.

## API (`src/game/pcol.h`)

```c
int   pcol_load(Pcol *c, u8 *file, int size);        // + считает плоскости (16 Б/треуг. RAM) и штампы (2 Б/треуг.)
int   pcol_raycast(Pcol *c, const float o[3], const float d[3], float *t, float min_ny); // отрезок o..o+d, −1 = мимо
int   pcol_floor(Pcol *c, float x, float z, float y_top, float y_bottom, float min_ny, float *h); // верхний пол
int   pcol_move(Pcol *c, const PcolCapsule *cap, float pos[3], float dx, float dz, float *vy, float dt, int *floor_tri);
float pcol_sphere_cast(Pcol *c, const float a[3], const float b[3], float r);  // свободная доля 0..1
int   pcol_cam_row(const Pcol *c, int tri);           // строка LockCamParam части под ногами
```

- **Контроллер** (`pcol_move`, `pos` = ноги): 3 сферы радиуса `radius` от `step + r` до `height − r` выталкиваются из НЕходибельных треугольников **только по горизонтали** (скольжение вдоль стен, 3 итерации); пол — луч вниз от `ноги + step` (ступени ≤ `step` поднимают, выше — стена), прилипание к полу `snap_down` (лестницы/склоны вниз), без пола — гравитация. Ходибельно: `normal.y ≥ slope_cos`. Потолки пропускаются (в арене низких нет) **[упрощение]**. Игровые числа (капсула 0,35 м, высота 1,8, ступень 0,45, уклон 50°) — **[версия]**, не из данных.
- **Сфера-каст камеры**: кандидаты из ячеек вдоль отрезка → отсев по плоскости и y → сфера шагом `r` (тонкую стену не проскочить) + 5 шагов бисекции. Треугольники, которых уже касается начальная сфера, игнорируются (пивот у стены не прибивает камеру).
- Не потокобезопасно (общий буфер кандидатов, ≤1024 на запрос).

## Цифры (PPSSPP, **не железо**)

Коллизия игрока + сфера-каст камеры (+ луч лок-она в кадр захвата): в среднем 0,40 мс за прогон арены, пик ~2,1 мс, когда камера прижата к стене в углу (кандидатов до ~850 проверок) **[emulated]**. Бюджет плана — ≤2 мс на железе; замер на PSP не делался.
